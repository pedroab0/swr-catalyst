# Bundle Size Monitoring

This project uses [size-limit](https://github.com/ai/size-limit) to monitor and control bundle size.

## Configuration

Bundle size limits are defined in `.size-limit.json`:

- **ESM Bundle**: Full library in ESM format (limit: 5 KB gzipped)
- **UMD Bundle**: Full library in UMD format (limit: 5 KB gzipped)
- **Individual Hooks**: Each hook separately (limit: 2 KB gzipped each)
  - `useSWRCreate`
  - `useSWRUpdate`
  - `useSWRDelete`

## Running Locally

```bash
# Build the package first
npm run build

# Check bundle size
npm run size
```

## In CI/CD

### Main CI Workflow
The `ci.yml` workflow checks bundle size on every push and PR to ensure the build doesn't exceed limits.

### Size Workflow (PR Comments)
The `size.yml` workflow runs on pull requests and:
- Compares bundle size with the base branch
- Posts a comment on the PR showing size changes
- Highlights if any bundle exceeds the limit

## Example Output

```
Package size: 4.2 KB (gzipped)
Size limit:   5 KB
```

## Adjusting Limits

To adjust size limits, edit `.size-limit.json`:

```json
{
  "name": "ESM Bundle",
  "path": "dist/swr-catalyst.js",
  "limit": "5 KB",
  "gzip": true
}
```

## Why This Matters

Keeping bundle size small ensures:
- ✅ Faster page loads for users
- ✅ Better performance on slow networks
- ✅ Lower bandwidth costs
- ✅ Improved Core Web Vitals scores
